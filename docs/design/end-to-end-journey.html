2 · Swing desk journey (happy path)

The core operator loop after data exists. Encodes ADR-054: screen judges; plan structures; trade papers.

0health
Is local cache usable?
Empty cache must not invent candidates. Stale cache should warn, not lie.
saham fetch status saham fetch market --universe lq45 saham fetch broker …
1orient
Daily briefing (read-only)
Does not fetch, tune, or persist. Optional cockpit: saham tui.
saham today --universe lq45 --top 5 saham tui
2discover
Universe board — rank candidates
Signal / Accum / Action / Phase / Gate. Phase sequence uses setup_phase_ledger (closed sessions), not observation full-scan.
production saham screen accum --universe lq45 TUI · s a · r refresh
3judge
Single ticker judgment desk
Deep judgment + optional diagnostic panels. Still screen, not plan.
production diagnostic ok saham screen accum TICKER saham screen accum TICKER --full TUI · Enter inspect (present-only)
4structure
Plan swing — geometry only (policy A)
Inherits Action from screen judgment. No re-score of ENTER/WATCH/AVOID.
production saham plan swing TICKER --capital 10000000 TUI · p plan
5paper
Human notebook — no broker orders
Paper only. Not corpus. Not policy apply.
paper saham trade accum log --from-plan …
∥browse
Raw local data — not a decision surface
View ticker / broker for facts. Never invent Action here.
saham view ticker show TICKER saham view broker list TUI · v t / v b
Success for this journey
  • Operator can name why Action is ENTER/WATCH/AVOID from screen evidence
  • Plan numbers do not contradict screen Action
  • No silent network; fetch was explicit
  • Paper log is optional and human-owned

3 · Pre-open journey

Separate product lane from swing desk. Session-scoped, identity-bound, opening-focused. Cron owns most of the machine path.

Acapture
Freeze pre-open candidates from IEV / NCP
cron corpus write saham fetch iev saham research pre-open capture
Btrack
Sample opening path (track files / confirm)
saham research pre-open track
Cassess
Human post-open confirm of frozen plan
Stdout / live assess — not a second research write.
cli saham assess pre-open --session YYYY-MM-DD
Dpaper
Optional pre-open paper notebook
paper saham trade pre-open log …
Elabels
Outcomes + cohort evaluate (learning only)
corpus saham research pre-open labels saham research pre-open evaluate saham research pre-open status
TUIboard
Pre-open board = IEV snapshot only (local)
Intentional delta vs full CLI research path. Enter = present-only inspect.
tui Ctrl+P · screen pre-open · s p
Do not conflate
  • Pre-open capture ≠ screen accum board
  • Assess pre-open ≠ plan swing
  • Labels/evaluate never recompute live Action for the desk

4 · Research / learning journey

Parallel lane. Builds a point-in-time corpus for evaluation and guarded policy work. Never a substitute for live screen judgment.

Accum corpus
  • research accum capture — session observations (runs assess)
  • Writes setup_phase_ledger (window 7) + learning_observations
  • research accum labels — forward outcomes
  • research accum evaluate — cohort study
  • backfill-phase-ledger — one-shot history migrate
Policy (guarded)
  • Portfolio sim first: backtest portfolio swing
  • policy accum tune → review → validate → apply
  • IS proposal, paired OOS validation, explicit apply
  • Not paper trading · not live TradeSetup

Capture vs live screen

Job Live desk Research capture
Score / Action Yes · production Yes · same assess path
Write observations No Yes · corpus
Write phase ledger Yes (window 7) Yes (window 7, same assess)
Operator board Primary Secondary (cron/evening)
Capture before cron is valid

Manual research accum capture runs assess and can mint ledger + observations. Cron order is the happy path, not a hard gate.

7 · Anti-patterns (product bugs)

If the journey feels wrong, it is often one of these confusions.

Anti-pattern Why it is wrong Correct path
Plan as second analysis Re-scores Action; confuses structure with judgment screen judge → plan structure only
Fetch on every open Silent network; non-reproducible desk local-first · explicit fetch
Research capture = only way to screen Couples desk to corpus writes live screen accum for desk
Labels drive Action Look-ahead / corpus authority leak labels for evaluate/policy only
View as decision surface Browse is facts, not TradeSetup screen / plan for decisions
TUI invents rows on empty cache Lies about readiness empty state → explicit fetch
Broker orders from app Out of product scope paper notebook only
Mine observations every screen Perf + wrong abstraction phase ledger (ADR-058)
